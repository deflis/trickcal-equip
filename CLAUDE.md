## Architecture

**トリッカル 周回ルート計算機** — a React SPA that recommends optimal stage farming routes in the mobile game Trickcal RE:VIVE, based on which blueprint items the player needs.

### Data layer (`src/types.ts`, `src/blueprints.ts`, `src/stages.ts`)

- **`src/types.ts`** — all shared types. `RankId = IntRange<2, 9>` (ranks 2–8; rank 1 is excluded since Stage 2 and below are out of scope). `BlueprintId` is the string literal type `` `${RankId}${EquipTypeId}` `` (e.g. `"81"` = rank 8 armor).
- **`src/blueprints.ts`** — two exports serve different purposes:
  - `BLUEPRINTS` — flat `Blueprint[]` array used for list rendering/search, generated by `generateBlueprints(MAX_RANK)`.
  - `blueprints` — a `BlueprintMap` keyed by `RankId`, then by equipment name (`armor`, `hat`, `ring`, `boot`, `accessory`, `sword`, `wand`). Used in `stages.ts` for **type-safe** drop data entry (e.g. `blueprints[8].sword`).
- **`src/stages.ts`** — drop data structured as `STAGES_BY_LEVEL: Stages` (nested by world/stage number), then flattened to `STAGES: Stage[]` for use in analysis. Many stages are marked `// TODO:` pending wiki data.

### State & analysis (`src/App.tsx`)

Three core states:
- `requirements: Record<BlueprintId, number>` — 必要数（needed count per blueprint）
- `holdings: Record<BlueprintId, number>` — 所持数（currently held count per blueprint）
- `shortages` (memo) — 不足数 = `max(0, requirements[id] - holdings[id])`

`activeShortages` (memo) further filters `shortages` to the selected rank (and its sub-rank when relevant). The `analysis` memo filters `STAGES` to those within `maxWorld-maxStageNum`, scores each stage by summing `activeShortages` for matching drops, and sorts by **stage level descending** (highest level first), since stamina cost is uniform across stages in this game.

Key derived values:
- `subRank` — one rank below `selectedRank`; its blueprints appear in the list only when they have requirements set
- `bestScoreId` — the stage with the highest shortage score (shown with BEST SCORE badge in `AnalysisPanel`)

### Holdings workflow

1. Set 必要数 via `addCharacterFullSet` or manual +/− input
2. Enter 所持数 (always editable, visible for every blueprint)
3. 不足数 is shown inline; stages are scored by 不足数 rather than 必要数
4. **消費ボタン** (`⚡消費`) — subtracts holdings from requirements (`requirements[id] -= min(req, held)`), then clears holdings; represents "I crafted with these items"
5. Holdings trash button — clears only 所持数 without changing 必要数

### AnalysisPanel badges

- **TOP LEVEL** (green) — the first result (highest stage ID in sorted list)
- **BEST SCORE** (amber) — the stage with the highest shortage score, shown when it differs from TOP LEVEL

### Adding new stage data

Add entries to `STAGES_BY_LEVEL` in `src/stages.ts` using the `blueprints[rank].slotName` pattern. Remove the corresponding `// TODO:` comment.

### Extending ranks

To add rank 9: update `MAX_RANK` in `src/types.ts`, add `'9'` entry to `RANK_CONFIG` in `src/blueprints.ts`, and extend `RankId` (currently `IntRange<2, 9>` already covers up to 8; change to `IntRange<2, 10>` for rank 9).
